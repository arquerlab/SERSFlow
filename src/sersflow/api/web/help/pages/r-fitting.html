Peak fitting

The Peak Fitting step describes a model (a sum of peaks and optionally a background), fits it to each spectrum and writes the fitted parameters as feature columns.

What the step does

  • Engines: vibrational pipelines use SciPy bounded curve_fit; XPS pipelines use lmfit, which adds the Vary checkboxes, parameter links, active backgrounds and the Fermi edge.
  • It replaces the spectrum with the fitted curve. Any later step (Normalization, Integration…) sees the model, not the data. Points outside the fit window keep their original values.
  • The exported columns come from re-fitting the step's input, so they are independent of later steps.
  • If a fit fails, the spectrum passes through unchanged without an error; its fit columns are empty and gof_success is 0. Check this in Analyze → Plots → Fit diagnostics.

Initial guesses

  • Centre (pos) starts at 1000 in every pipeline, including XPS. Always set it near the real peak (or use a recipe).
  • Amplitude is the peak height. The Auto checkbox lets SpecFlow estimate it. Typing 0 or a negative number switches Auto back on.
  • Widths (FWHM): the vibrational engine has no safety limits, so set an upper bound; XPS applies sensible limits automatically.
  • With Vary off in a vibrational fit, the value is fixed.

GL(m) product versus SGL(m) sum

CasaXPS has two Gaussian–Lorentzian line shapes (CasaXPS Cookbook 2026, p. 67). With u = (x − pos)/F and p = m/100:

  • GL(m), product: exp(−(1 − p)·4 ln2·u²) / (1 + 4p·u²). This is what CasaXPS writes as GL(30) and what the Biesinger recipes were fitted with. SpecFlow component gl.
  • SGL(m), sum: p·L + (1 − p)·G with a shared FWHM. SpecFlow component sgl.
  • GL(m,n): GL(m) convolved with a Gaussian of FWHM n (fwhm_g, in eV). SpecFlow component gl_gauss.

For the product form, CasaXPS's F is not the full width at half maximum: the true FWHM is slightly smaller (about 0.96·F at m = 30). SpecFlow's fwhm is always the true FWHM, the value Biesinger tabulates and CasaXPS shows in its component table. SpecFlow derives F internally. Areas use the closed form ∫ = (π/√b)·erfcx(√(a/b)) with a = 4 ln2 (1 − p), b = 4p, so area ratio links work for gl as well.

Pipeline schema v2. Before v2, SpecFlow's gl was the sum form. On the first server start with v2, every stored pipeline, session and run snapshot is rewritten gl → sgl and a_gl → a_sgl, so old results reproduce exactly. Their pipeline hash changes; runs keep the hash they were made with. Pipeline packages exported as sersflow.pipeline.v1 are converted the same way on import. A new gl anywhere (UI, MCP, v2 packages) means the product form. Re-applying a recipe gives the product form.

Links (XPS only)

In the Link column choose a target “<peak>.<parameter>” and a relation: equal, scale (× factor) or offset (+ value). The linked parameter then follows its target and is no longer free. Typical use for a doublet: FWHM equal to the main component, position offset by the spin–orbit splitting. A scale link on amplitude fixes a height ratio. For an area ratio (e.g. a satellite locked to its main peak by the literature area ratio) use the area ratio relation on an amplitude: the dependent area is ratio × the driver area whatever FWHM and line shape each peak ends up with. Recipes lock satellites this way by default.

Previewing a fit

There is no interactive fitting. Set View → After: fitting (or Final if the fit is the last step). SpecFlow fits each spectrum of the subset once and draws data, total fit, individual components and a residual panel with diagnostics. It refreshes when you change the view or subset, or press Run preview plot (subset), not after every parameter edit.

Start with one peak on one spectrum, check the residual, then add peaks one at a time. Narrow the fit window rather than adding background peaks.

Fitting results

Per component: fit_[region_]<peak>_<param> and …_area (all peak types except DS and GDS). Per fit: fit_[region_]gof_<rmse|r2|r2_adj|aic|bic|aicc|chi2|redchi|…>. See Exports and column names. AIC and BIC assume unit variance, so compare models only on the same data. There are no per-parameter error columns, only gof_median_rel_stderr. A failed fit has empty columns and gof_success = 0 (see Failed fits).

Fit health

Failed fits

A fit that cannot run (invalid set-up, optimizer error, empty spectrum) is recorded, not hidden. The fitting step still passes the raw spectrum through, so later steps and plots keep working, but in an analysis run:

  • all of that fit's parameter and area columns are empty and gof_success = 0;
  • the run carries a warning and a fit_failures summary (counts plus the affected spectra and the reason). Analyze shows an amber ⚠ n fits badge in the run list and the details under Overview;
  • fit_health.csv in the fit-curve export lists the spectrum with fit_status = failed and the reason;
  • MCP get_analysis_runs_by_id and post_analysis_jobs_wait return the same warnings.

A fit that ran but did not converge (success = 0 from the optimizer) is flagged as not converged; its parameters are kept so you can inspect them. A fitting step whose window does not overlap the spectrum (for example an O 1s recipe meeting a C 1s spectrum in a multi-region pipeline) is not applicable: it is skipped silently and is not a failure. Restrict steps with the region selector to keep this explicit.

Every fit also reports gof_n_at_bound (free parameters sitting on a bound: the model is asking for more freedom than it has), gof_bg_gt_data_frac (fraction of points where the fitted background is above the data), gof_resid_mean_edge_lo / gof_resid_mean_edge_hi (mean residual over the outermost ~5% of the window at the low / high x end) and gof_resid_lag1_autocorr (≈0 for noise, close to 1 for a structured residual). The fit-diagnostics badge turns amber when a parameter is on a bound, the background is above the data in more than 10% of the points, or the residual autocorrelation exceeds 0.7. A background above the data at the window edge usually means the peaks are missing intensity (for example satellites that are too weak) and the background is compensating; fixing the background alone will not cure it. The fit-curve export zip also contains fit_health.csv.

Step numbers and column prefixes

The observation columns of a fitting step are prefixed s{N}_ where N is the 0-based position of the step in the pipeline (step_index). The step number used by the fit-curve and preview endpoints (fitting_step_num) is 1-based. GET /analysis/runs/{id}/fitting-steps lists both and the column_prefix; the endpoints also accept fitting_step_index instead of fitting_step_num.

Parameter sweep

POST /analysis/runs/{id}/sweep-jobs (MCP: post_analysis_sweep_jobs) fixes parameters of one fitting step on a grid (e.g. the shared FWHM) and refits the run's spectra at every grid point. The result zip has sweep_summary.csv (per grid point, sorted by mean RMSE, with the fit-health columns) and sweep_points.csv. Calibration and earlier steps are not recomputed.

Common messages

MessageDo this
“Insufficient points for fit…”Widen the crop or fit window, or use fewer parameters.
“Nonlinear fit did not converge…”Improve the initial centres and bounds, widen the window, simplify the model.
“Fitting failed for <id>…”Inspect that spectrum; it may be noise or outside the region.
“No spectra match fitting region X…”Check the Region / band name against your dataset's regions.
