Tutorial 5 · Reuse, share and export

Goal: apply a pipeline you already built to new data, hand datasets and pipelines to colleagues, and keep your work reproducible. About 15 minutes.

Reuse a pipeline on new data

  1. Upload the new files and create a dataset (the technique must match the pipeline's).
  2. In the Pipeline card, pick the saved pipeline in the Saved list. It loads immediately and replaces whatever is in the editor.
  3. Preview on a subset (Create subset). Adjust only what the new data needs (crop range, baseline lam, fit window).
  4. If you changed anything, save under a new name (for example run43_v1) rather than overwriting. Then run it in Analyze.
Leave Overwrite if name exists unticked unless you really want to replace the stored steps. Earlier runs and your notes refer to the name.

Share a pipeline

  • Export selected (or Export current pipeline) downloads a .sersflow-pipeline.json file. Send it to a colleague (or attach it to a paper's SI).
  • They press Import pipeline, then Reload to load the steps into the editor.

Share a dataset

  • Export dataset downloads <name>.sersflow-dataset.zip: the source files plus their labels.
  • A colleague presses Import dataset and gets an identical dataset (and a fresh session).

Edit labels of an existing dataset's files

Hid or purged the files? Select the dataset and press Restore files to uploads. The files and their labels reappear in the Uploads tab for editing.

Keep a record

  1. Name datasets and pipelines meaningfully and with a version (run42, run42_v1, run42_v2).
  2. In Analyze → Exports, Load manifest (JSON) shows the run, dataset, pipeline hash and feature list. Keep the manifest (or the Bundle ZIP) next to your results.
  3. Export the pipeline JSON to your project folder together with the observation CSV.

Housekeeping

  • The server keeps at most 50 runs per dataset and deletes the oldest automatically. Download anything you need to keep.
  • Running PCA again overwrites the previous PCA result of that run: download first.
  • Hide ≠ delete. Purge hidden unused is permanent.
