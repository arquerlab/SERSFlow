MCP server: setup

The SpecFlow MCP server lets an AI assistant (Cursor, Claude Desktop, Claude Code, or any other MCP-capable LLM client) operate SpecFlow with tools instead of clicks. It speaks MCP over stdio and wraps the same HTTP API the web interface uses.

1. Install

From the repository root, in the Python environment you use for SpecFlow:

pip install -e ".[mcp]"

This installs the sersflow-mcp command (also runnable as python -m sersflow.mcp). Optional extras: [parquet] for Parquet exports, [explore-fda] for functional PCA.

2. Decide how the API is reached

  • Start the API yourself (recommended while learning): sersflow-api. The MCP connects if GET /health answers; it never starts a duplicate.
  • Let the MCP start it (default, api_start_enabled = true): on the first tool call, if the API is down, the MCP launches python -m uvicorn sersflow.api.main:app and stops it again when the MCP exits. Its output goes to api_spawn.log in the export folder.

3. Environment variables (secrets and addresses)

VariableMeaning
SERSFLOW_URLAPI address. Default http://127.0.0.1:8000.
SERSFLOW_USERNAME + SERSFLOW_PASSWORDLog in when the server requires authentication. Set both or neither.
SERSFLOW_AUTH_DISABLED=1Read by the API, not by the MCP. Runs the API open, for local use. Because the MCP passes its environment to an API it spawns, set it in the client's env block.
SERSFLOW_MCP_CONFIGPath to the TOML settings file (below). If set and the file is missing, the MCP refuses to start.
Put passwords only in the client's env block, never in the TOML file and never in a chat message.

4. TOML settings (non-secret)

Copy config/sersflow_mcp.example.toml to sersflow_mcp.toml and point SERSFLOW_MCP_CONFIG at it. Unknown keys are ignored silently.

KeyDefaultMeaning
export_dir./.sersflow_mcp_exportsWhere exports, plots and logs are written. Use an absolute path.
http_timeout_s30Timeout of each request to the API.
job_wait_timeout_s3600Default maximum wait of the *_wait tools.
job_poll_interval_s0.25How often a wait tool checks the job.
api_start_enabledtrueAllow the MCP to start the API.
api_health_timeout_s60How long to wait for a started API to answer.
upload_confirm_bytes104857600 (100 MiB)Uploads, dataset imports and plot files above this need confirm=true.
fitting_confirm_max_components20A pipeline whose fitting step has more components than this needs confirm=true.
tabular_max_rows / tabular_max_cols50 / 30Default size of what read_tabular_file returns to the model.
analysis_async_defaulttrueWhether analysis runs and matrix jobs start in the background by default.

5. Connect your client

All clients need the same three things: the command (sersflow-mcp), the environment from section 3, and a restart of the client afterwards. Use the full path to the executable when the client does not inherit your shell's PATH (typical for desktop apps). Find it with where sersflow-mcp in the activated environment.

Cursor

Create .cursor/mcp.json in your project (or ~/.cursor/mcp.json):

{
  "mcpServers": {
    "sersflow": {
      "command": "sersflow-mcp",
      "env": {
        "SERSFLOW_URL": "http://127.0.0.1:8000",
        "SERSFLOW_AUTH_DISABLED": "1",
        "SERSFLOW_MCP_CONFIG": "C:/Users/you/Documents/SERSFlow/config/sersflow_mcp.example.toml"
      }
    }
  }
}

If sersflow-mcp is not on PATH, use "command": "python", "args": ["-m", "sersflow.mcp"] with the full path of the right interpreter.

Claude Desktop

Edit claude_desktop_config.json (Settings → Developer → Edit Config; on Windows usually under %APPDATA%\Claude\), then restart the app completely. In JSON, write Windows paths with forward slashes or doubled backslashes.

{
  "mcpServers": {
    "sersflow": {
      "command": "C:/Users/you/venvs/sersflow/Scripts/sersflow-mcp.exe",
      "args": [],
      "env": {
        "SERSFLOW_URL": "http://127.0.0.1:8000",
        "SERSFLOW_AUTH_DISABLED": "1",
        "SERSFLOW_MCP_CONFIG": "C:/Users/you/Documents/SERSFlow/sersflow_mcp.toml"
      }
    }
  }
}

Claude Code

claude mcp add sersflow --env SERSFLOW_URL=http://127.0.0.1:8000 --env SERSFLOW_AUTH_DISABLED=1 --env SERSFLOW_MCP_CONFIG=C:/Users/you/Documents/SERSFlow/sersflow_mcp.toml -- sersflow-mcp

Then run claude mcp list to confirm it connects.

Any other LLM client or framework

Launch sersflow-mcp as a child process, speak MCP over its stdin/stdout, and pass the environment variables above. Start it in a writable working directory. Logs go to stderr, so stdout stays clean for the protocol.

The Claude Desktop and Claude Code commands follow those products' usual conventions; the repository itself only documents Cursor. If a client's menu has changed, check its own MCP documentation. The server side (command, env, TOML) is the same everywhere.

6. Check that it works

  1. Open the client and confirm that a server named sersflow (display name “SpecFlow”) is listed with its tools.
  2. Ask: “Call get_mcp_meta and tell me the auth mode and any warnings.” This is the first call, so it also starts the API if needed and logs in.
  3. Ask: “List my SpecFlow datasets.”

7. Good habits

  • Set an absolute export_dir and an absolute SERSFLOW_MCP_CONFIG. Relative paths resolve against whatever folder the client launched the MCP from, which is often not the one you expect.
  • Add a standing instruction to your assistant: “Propose a plan and wait for my approval before creating datasets, running analyses or fitting.” The server does not enforce this; it is a convention.
  • Keep MCP and API from the same checkout. A different major version makes every tool except get_health and get_mcp_meta answer incompatible.
