Tutorial 1 · SERS / Raman: files to correlation

Goal: turn a folder of Raman/SERS files into a table of peak areas, check how two bands relate, and export the result. About 30 minutes. FTIR data follow the same path.

You will need: your spectra (.txt with a wavenumber header, or Renishaw .wdf), preferably with experiment details in the file names (see Labels and file naming).

1. Upload and check labels

  1. Open the Uploads tab. Choose your folder with the folder picker (extension filter Only, txt,wdf) and press Upload.
  2. In Uploaded files & metadata, read the summary beside each file: sample, pH, potential, laser… Wrong or missing? Tick the file, correct the cells in Edit labels and press Save.
Fix labels now. They become the meta_* columns of your results and the colours and filters you use later.

2. Look at the raw spectra

  1. Open Raw visualization and select a file. For a series or map, tick a handful of points.
  2. Try Overlay and Stack. Note: spikes? slanted background? weak or empty spectra?

3. Create a dataset

  1. Open Prepare. In Create new dataset tick the files (one file is enough for a series or map).
  2. Type a Dataset name, for example run42, and press Create dataset.
  3. Press Create subset. The plot card now shows Raw (subset) spectra: a random handful used only for previews.

4. Build the pipeline

Add steps from the palette in this order, previewing after each. Set View to After: <step> to see exactly what a step did.

  1. + Cropping: fill min_x and max_x with the region you trust (for example 400 and 1800).
  2. + Cosmic Ray Removal: keep zscore, threshold 5, window 5 (odd). Check on a spiky spectrum that spikes vanish and real bands stay.
  3. + Smoothing: window 11, polyorder 3. Increase the window only while peak shapes still look the same.
  4. + Baseline Correction: start with asls, lam 1e6, p 0.01. Use After: baseline to see the baseline curve; raise lam if it follows the peaks, lower it if it misses broad background.
  5. + Normalization: max for a first look (use vector (L2) if you plan PCA).
  6. Features: + Peak Integration with one window per band (for example band1 = 1050–1110, band2 = 1550–1620), or + Peak Fitting to fit them (see Peak fitting).
Peak Integration does not remove a baseline by itself; that is why Baseline Correction comes first.
  1. Switch View to Final and check several subset spectra (press Resample for new ones). Save the tricky ones as tiles and re-check them whenever you change something.
  2. Type a name such as run42_v1 and press Save to library, then Save pipeline.

5. Run it on all spectra

  1. Open Analyze. Choose your Dataset and the Pipeline you saved.
  2. Press Run feature extraction (async). Watch the progress line; the run appears in the Runs table. Wait for status completed.
If the run fails, read the message in Overview. Typical causes: crop that does not cover the data, a fit window left with no points, or a pipeline that was not saved. Fix, then start a new run.

6. Explore

  1. Section → Correlation / VIF. Select your two band areas (and maybe a metadata column such as potential) and press Run correlation. The heatmap shows Pearson r.
  2. Section → Plots → Parameter vs parameter: X = area_band1, Y = area_band2, Color = meta_potential_V, press Plot.
  3. Optionally PCA / Cluster with scaling StandardScaler to see which spectra group together. Remember the default plots start at PC2 vs PC3.

7. Export

In Exports press Observation wide CSV (labels + axes): one row per spectrum with your features, meta_* labels and axes. Also download the manifest if you need to document how it was made. Column meanings: Exports and column names.

What you learned

  • Preview on a subset, run on everything.
  • Order matters: crop → spikes → smooth → baseline → normalize → features.
  • Name and save your pipeline: it is the record of your processing.
