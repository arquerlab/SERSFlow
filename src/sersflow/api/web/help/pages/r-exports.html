Exports and column names

Everything you download from Analyze is UTF-8, comma-separated, with a header row. Missing values are empty cells. Use the observation table whenever you want features and labels together.

Observation wide CSV

One row per spectrum. Column order:

  1. spectrum_id
  2. Feature columns in pipeline order (see below).
  3. Axes: axis_time_s, axis_map_x, axis_map_y, grid_nx, grid_ny, file_kind (single, series or map).
  4. Labels: meta_*, one column per label found in any file, alphabetical. Empty where a file lacks that label.
The observation table has no file-name column. If you need to know which file a row came from, put it in a label (for example sample) or use the PCA scores CSV, which includes the file path.

meta_ columns

These are the labels you saw in the Uploads tab (sample, gas, pH, potential, laser…). Names are made safe by replacing every run of characters other than letters, digits and underscore with _, then prefixed with meta_. Labels holding lists or dictionaries are written as JSON text.

When a pipeline has several steps of the same kind, names are prefixed s<N>_ (the step number). If two names would still collide, a suffix __2, __3… is added.

Give fit components short, meaningful IDs (for example CO_top or Co3O4) in the fitting editor: they end up in every column name.

Observation long CSV

Columns: run_id, dataset_id, spectrum_id, feature_key, value, kind, where kind is feature, axis or meta. The features-only long file has run_id, spectrum_id, feature_key, value, kind.

Manifest

A JSON record of the run: run_id, dataset_id, pipeline_hash, subset_hash, created_at, finished_at, feature_columns and the file format (encoding, delimiter, how missing values are written). Keep it with your results for reproducibility.

Uncertainties

There are no per-value error columns. The only uncertainty summary is the fit column fit_[region_]gof_median_rel_stderr, the median relative standard error of the fitted parameters.
