Tutorial 6 · Work with an AI assistant (MCP)

Goal: let an assistant do the clicking. You describe the science, it calls SpecFlow's tools, and you approve the important steps. About 20 minutes the first time.

Before you start

  1. Install and connect the MCP server for your client: MCP server: setup.
  2. Start the SpecFlow API (sersflow-api), or let the MCP start it.
  3. Open the web interface in a browser too. Everything the assistant creates (datasets, saved pipelines, runs) appears there, which is the easiest way to check its work.

Step 0: set the ground rules

Paste this once at the start of the conversation (or into your client's standing instructions):

You are operating SpecFlow through its MCP tools.
- Start with get_mcp_meta.
- Reuse existing datasets and pipelines when they fit.
- If I did not name a method (baseline, smoothing, fit model...), ask me.
- Propose a plan and wait for my approval before creating datasets,
  running analyses or fitting.
- Never overwrite a saved pipeline: save changes under a new name.
- When a tool asks for confirm=true, tell me why and wait for my yes.
- Waiting for jobs: use timeout_s=30 and call again until it finishes.
- Give every export its own output_path.

Example A: vibrational data to a correlation

  1. Look around. “List my datasets and saved pipelines. Don't create or run anything. Which pair looks best for baseline-corrected SERS peaks near 1080 and 1580 cm⁻¹?”
  2. Upload. “Upload C:\Data\SERS\run42 (all .txt) and create a vibrational dataset called run42. Show me the spectrum axes and the label fields it found, then stop.” Check in the Uploads tab that the labels are right.
  3. Plan. “Propose a pipeline for run42: crop, despike, baseline, normalization, fits for the 1080 and 1580 bands. Ask me which methods you should use.” Answer its questions (see Baseline methods if unsure).
  4. Try it. “After I approve: create a session, run a QC preview and a metrics-only run on a subset, and tell me what you see. Then save the pipeline as run42_v1.” The pipeline shows up in Prepare → saved pipelines.
  5. Run on everything. “Run the analysis on the whole dataset. Poll with timeout_s=30, repeat for up to 10 minutes, then report the job id.” You can watch it in Analyze → Runs.
  6. Answer the question. “Export the observation table to run42_obs.csv and report the Pearson correlation between the two peak areas and the file path.”

Example B: PCA on a finished run

“Run PCA on analysis run <run id> with standard scaling and 3 components. Summarise the variance explained and export the scores as scores_run42.csv.”

Example C: XPS fitting with a recipe

  1. “Dataset <id> has Ag 3d and O 1s. Search chemical states for Ag 3d and suggest a fitting recipe from the index. Wait for my OK.”
  2. “Apply the recipe to session <id>.” Remember that this replaces an existing fit for that region. If SpecFlow asks for confirm=true, the assistant should explain why and wait.
  3. “Run the analysis and produce the fit-curve plots with data, fit, components and residuals.”

What good looks like

  • The assistant reports ids and file paths, not pasted tables.
  • It asks before choosing methods and before heavy runs.
  • You can reproduce anything it did by opening the same dataset, pipeline and run in the web interface.
When something fails, ask the assistant to show the exact error message and the tool it came from, then look it up in Error messages.
